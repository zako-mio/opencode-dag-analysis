## 五、反思/分析/建议

1. **headless 渲染失败的根因排查教训**：cytoscape 遇"悬空边"（引用不存在节点）会抛 `Can not create edge` 错误中断**整个图渲染**（不是只跳过该边）。排查路径：先怀疑样式类→再怀疑数据→最后 console 日志抓到根因。**教训：DAG 数据生成后必须先做悬空边清洗门控，再进渲染**。
2. **测试文件路径陷阱**：测试 HTML 若放在无 vendor 的目录，`cytoscape is not defined` 会误导排查方向（以为是页面问题，实为 vendor 路径缺失）。**教训：测试环境必须与生产环境一致**。
3. **zcount 更新时机**：layoutstop 事件可能错过，需 setTimeout 兜底。
4. **browser-harness js() 陷阱**（复用 MEMORY 经验）：复杂箭头函数 heredoc 转义易错 → 用简单表达式 + 分块抓取；最终改用 chrome headless `--dump-dom`（0816 成熟模式）更可靠。
5. **委托协议效果**：主Agent 保持纯净（35 包语义、61 装配语义、历史还原全部子Agent 并行完成），主Agent 只做机械脚本 + 决策 + 聚合，上下文可控。
6. **用户反馈驱动的质量改进**：skill 关系边（33 条）让主 DAG 从"碎片化外源依赖"变为"有内部协作网络的装配体系"；大包组级视图解决了数百模块无法渲染的问题。
7. **未来改进**：①外部服务节点可更细（bun/typescript/dotnet 等次要外部也可入图）②装配层↔装配层边可更丰富（skill 间引用）③可加官方包内部热点模块 Top N 分析。
