七、结论与下轮建议

结论：本轮为「官方 v1.18.30 → v1.18.35 点检 + 装配层再全量重建 + 需求发现能力入图」三合一。官方侧 328 文件变更未触及包集合与包间依赖（36 包集合与 v1.18.29 逐一致），官方三图仅升级版本标注；装配层由 83 重建为 87 组件（能力细分归入既有组，组总数仍 42）；DAG 演进为 133 节点 / 177 边 / 8 层 / 42 组，diff 图维持 46 / 68 / 20；门控 33/33 ALL PASS、headless ALL OK。

下轮建议：

  1. 补 plugin kind：把 system-date-transform.ts / notify-on-pause.ts 纳入 pipeline（新增 kind + 组 + 节点页），使装配层对「插件」这一类载体不再有盲区。
  2. 清理生成脚本的退役残留：修订 build-dag.py 的 asm_to_pkg / 委派名单 / asm_ext_rules，并同步 s2-merge-assembly.py docstring 与 stage-03-new-assembly.json，避免「靠清洗逻辑兜底」长期化。
  3. 单一真相源治理统计口径：把 official 的 stats.layers 校准（0 → 实际层数），并让 README 的门控条目数从门控脚本输出派生，消除「文档数与实测数分叉」。
  4. OpenCode 2 单独立项：上游 v1.19.0 是主版本跃迁入口（opencode upgrade --major），须做破坏性契约审计（配置 schema、agent/skill 契约、plugin API）后再决定是否升级本机装配层。
  5. 内部结构按需重采：若下一版涉及 core / opencode 主包的跨模块 import 变化，重跑 s1-parse-internal.py 并把版本串统一到当轮基线（同时治理 stage-00-version-baseline.json 仍为 v1.18.29 的漂移）。
  6. drawio 链路治理：05-drawio 主图与装配图仍是 0911 手工版，建议先补生成脚本（或明确降级为「静态留存、不随轮更新」并在 README 标注），避免「图与数据不同步」。
