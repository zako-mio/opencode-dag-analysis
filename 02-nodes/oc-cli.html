⑤ 为什么存在（why）

设计意图（官方）

作为 v2 时代的命令行入口，复用 effect CLI 生态以类型安全方式声明命令，并将实际逻辑委托给 core/server/tui 包，保证 CLI 层只做装配不做业务实现。

改造关联

属官方底座，本机装配层未引用（本机不安装 lildax 二进制）。但本机装配层使用 opencode v1 CLI（@opencode-ai/opencode 的 yargs 命令），cli 是 v2 演进方向，改造时需注意双 CLI 并存。

⑥ 怎么用（how）

怎么用

· bin: lildax（package.json:7-9 bin.lildax → ./bin/lildax.cjs），build 产出跨平台二进制（script/build.ts:12 binary=lildax、:80 outfile dist/{name}/bin/lildax、:86 OPENCODE_CLI_NAME）
· 命令树：src/commands/commands.ts:6-50 Spec.make 声明 api/debug/migrate/service/serve 子命令，index.ts:10-25 Runtime.handlers 映射懒加载 handler
· TUI 入口：src/tui.ts:1-18 runTui() 导入 @opencode-ai/tui run + AppNodeBuilder.build(Global.node) 装配完整环境

典型场景与协作

作为 v2 时代的命令行入口（OpenCode 2.0 preview）：serve 命令拉起 v2 API 服务器、service 管理后台守护进程、api 命令直接调 OpenAPI、tui 启动终端交互界面。与 web/desktop 互补：cli 是终端用户入口，内部委托 core/server/tui 包实现逻辑而非自己实现。
