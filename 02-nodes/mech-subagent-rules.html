subagent-rules 装配层

mech-subagent-rules · mechanism · AQ-自进化机制 · Layer 0

① 作用

子Agent 身份约束/工具使用/错误处理/通信规范(JSON)+结构化返回

② 提供能力

暂无

节点机制证据

④ 被依赖（下游）

无下游依赖

⑤ 为什么存在（why）

历史引入动机

为统一所有 task() 创建的子 Agent 行为，消除身份冲突(子 Agent 不再收调度者角色指令)，并规范输出为可聚合的结构化 JSON。

当前需求驱动

当前约束：子 Agent 仅执行分配任务不委派/不调度/不调用其他 Agent，不使用 search-agents 等搜索机制，严禁直接改 MEMORY.md 或 pending.json 之外记忆文件(记忆条目写 memory_pending/ 待审)；所有输出必须返回结构化 JSON；工具使用优先已加载专用工具、结果超长截断、读优先于写；错误处理自修复 3 次后记 errors 上报；通信用 JSON，summary≤200 字。

⑥ 怎么用（how）

触发方式

任何通过 task() 创建的子 Agent(plan/build/pdf-worker/drawio-worker/vision-worker/general/explore/reflection-worker/search-worker)被委派时作为共享前缀规则生效。

工作流/用法

①身份约束：执行者身份不委派不搜 Agent，记忆产出入 memory_pending/；②工具：优先专用工具/结果超长截断/读优先于写；③错误：自修复失败 3 次记 errors 上报不无限重试；④通信：输出结构化 JSON，summary≤200 字，files_created/modified 绝对路径，data 仅核心结果，decisions/warnings/errors 分级。

协作关系

指令源 instructions/auto-mode.md『Universal SubAgent Rules』；子 Agent 定义于 opencode.jsonc agent；与故障自愈(mech-fault)、输出控制(mech-output)、编码纪律(mech-coding-discipline)、MEMORY 硬门禁(mech-memory-gate)共同作用于子 Agent。
