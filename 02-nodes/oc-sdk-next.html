sdk-next

oc-sdk-next · package · G3-客户端 · Layer 4

① 作用

Effect 原生的进程内 OpenCode host SDK（过渡包，替代生成式 @opencode-ai/sdk）。src/opencode.ts 的 create() 用 AppNodeBuilder 构建 ApplicationTools/PermissionSaved 上下文，把 server 的 createEmbeddedRoutes 编译成 Web handler 并注入内存 fetch，客户端由此在进程内执行全部路由而无需监听端口/网络 I/O。src/index.ts 聚合 OpenCode 与 Tool 模块并再导出 client 的 Effect 类型。

② 提供能力

· 进程内 OpenCode host：OpenCode.create()（src/opencode.ts:10）
· 内存路由执行：Server router → Web handler → fetch（src/opencode.ts:20-38）
· 本地工具注册 tools.register（走 ApplicationTools 服务，src/opencode.ts:41）
· DI Layer：OpenCode.layer/Service（src/opencode.ts:47,49）
· Tool 门面：Failure/RegistrationError/make 再导出（src/tool.ts:1）
· Effect client 类型再导出（ClientError/Session/Model 等，src/index.ts:4）

⑤ 为什么存在（why）

设计意图（官方）

把 HTTP 服务抽象成可内存执行的 fetch handler，是 Effect 生态服务即组合的体现：客户端与服务器共享同一路由定义，测试无需起端口；ApplicationTools/PermissionSaved 以 Layer 注入，宿主可注册自定义工具并随 Scope 关闭释放资源。

改造关联

本机未改。装配层没用 sdk-next，但本机自定义工具/插件机制（plugins/vision-interceptor.js 的 chat.message + experimental.chat.messages.transform 钩子）与 host 内嵌、挂载钩子的宿主模式同源。

⑥ 怎么用（how）

怎么用

import { OpenCode } 后 OpenCode.create() 在进程内把 @opencode-ai/server 的 HttpRouter（createEmbeddedRoutes）经 HttpRouter.toWebHandler 转成 fetch 处理器，再用 @opencode-ai/client/effect 的 OpenCode.make({baseUrl:http://opencode.local}) + FetchHttpClient.layer 把请求打到内存 handler——零监听端口零网络 IO，完整保留路由/中间件/handler/codec/error。同时导出 Tool 命名空间（tools.register 走 Core 的 ApplicationTools 服务）与 ClientError/AbsolutePath/Model/Provider 等 Effect 类型；提供 OpenCode.layer 供依赖注入。

典型场景与协作

进程内嵌式 opencode 宿主：单元测试（sessions.get/prompt/interrupt/events 重放）、桌面端/插件宿主把 opencode 作为库而非服务调用；README 明示 transitional package，将替代生成的 @opencode-ai/sdk。
