⑤ 为什么存在（why）

历史引入动机

为管理 browser-harness(browser-use)进行网页交互时 Chrome 标签页的生命周期，避免标签页堆积占用资源。

当前需求驱动

当前原则：用完即关(new_tab 打开并提取后关闭标签页)；批量关闭提示(整个任务浏览器读取全部完成后必须用 question 询问关闭所有标签页保留第一个)；批量爬取中途不逐页关闭(影响速度)；WSL2 浏览器自动化统一 agent-browser，browser-harness 降为 Windows 备选。

⑥ 怎么用（how）

触发方式

使用 browser-harness/browser-use 进行网页交互(new_tab 打开页面、批量爬取、访问多个详情页)时触发。

工作流/用法

①每次 new_tab() 完成数据提取后关闭该标签页(跑 close-chrome-tabs.ps1 -KeepFirst)；②所有浏览器读取全部完成后用 question 询问用户「是否关闭所有标签页？」；③批量爬取中途不逐页关，等整个任务阶段完成后统一关闭；④标签页参数(-All/-KeepFirst/-KeepUrlPattern/无参列出)。

协作关系

指令源 instructions/browser-management.md 与 opencode.jsonc agent.plan/build.prompt 内『浏览器标签页管理』；依赖脚本 close-chrome-tabs.ps1；WSL2 用 agent-browser、Windows 备选 browser-harness(skill/browser-harness)；与代理纪律(mech-proxy)、浏览器自动化 skill 协作。
