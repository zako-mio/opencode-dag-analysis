⑤ 为什么存在（why）

历史引入动机

0911 opencode 架构能力扩展实战——诊断「架构」能力为孤儿/半成品（仅有知识图谱与 skill 草案，缺可见子Agent/行为层/门控），按五要素三层栈补齐为独立的架构判断执行者。

当前需求驱动

需求驱动：需要独立子Agent 承担架构判断与设计裁决，产出 ADR / 多维权衡矩阵 / 边界设计说明并自检；hidden=false 可见，用户可用 @architect-worker 直接召唤；无 model，继承父会话模型；权限收敛（task 全 deny 不可再委派，bash 仅 git status/diff allow）。

⑥ 怎么用（how）

触发方式

主Agent 判定架构类任务时委派；或用户 /arch 命令、@architect-worker 直接召唤；openspec design 阶段由行为层强制委派。

工作流/用法

①加载 architecture-judgment skill 按其 workflow.md 4 步执行；②判场景（18 场景）→ 定产出类型；③读速查/深链节点 → 按 schema 产 ADR（+矩阵）或边界说明，TEC 节点仅入 standards_refs；④自检；⑤返回结构化 JSON（artifact_path/matrix_path/graph_refs）。架构图不由本 Agent 产出，由主Agent 另委 drawio-worker。

协作关系

依赖 skill-architecture-judgment（方法论与契约）、instr-architecture-behavior（行为层触发）、command-arch（显式入口）、gate_architecture.py（门控）与 opencode.jsonc agent 段定义；架构图另委 drawio-worker（含 drawio-reference 强制加载）；依赖 config-main。
