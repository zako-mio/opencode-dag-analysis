⑤ 为什么存在（why）

历史引入动机

源自 0910-软件工程架构方法论知识图谱（167 节点/360 边/18 组/11 域/三层）交付与 0911 opencode 架构能力扩展实战：把「架构判断力」从速查+路径路由升级为 opencode 可执行的架构能力三层栈（能力 Skill + 可见子Agent + 行为层），并补齐显式命令与机检门控。

当前需求驱动

当前由五元组成：skill-architecture-judgment（可执行工作流 + 内置 167 节点离线图谱 + schemas/templates/gate）、agent-architect-worker（可见子Agent，继承父会话模型，产出 ADR/多维权衡矩阵/边界设计说明）、instr-architecture-behavior（行为层全局强制：架构任务必加载 skill + 委派 worker + 门控）、command-arch（/arch 显式入口）、gate_architecture.py（--kind adr|boundary 机检门控，PASS 前不得交付）。知识分层刚性：方法论层 MTH 与本质层 ESS 重召回，技术实践层 TEC 仅作 standards_refs 选型标尺、不得进入 decision/rationale。

⑥ 怎么用（how）

触发方式

三条触发：①自动路由——任务涉及技术选型/架构风格/模块与服务边界与粒度/架构评审/质量属性权衡/技术债治理/演进治理时，主流程(plan/build)自动加载本 skill 并委派 architect-worker；②显式命令 /arch <任务描述> 或 /arch 选型|评审|边界|技术债 ...；③openspec design 工件生成或修改时由行为层 architecture-behavior.md 强制触发。

工作流/用法

①判场景：把问题归入 routing.md 的 18 个任务场景之一（先匹配触发问法）；②定产出类型：adr(+矩阵) / boundary 为门控级，review / tech-debt 为模板级；③委派 architect-worker，prompt 含 Skills to Load、对应模板与 schema、TEC 引用约束；④产出后必跑 gate_architecture.py（--kind adr|boundary，schema 与 graph 自动解析），FAIL 回传修正最多 2 轮，不得降级口头通过；⑤交付主产物 + 多维权衡矩阵（涉选型）+ 门控证据 + 命中场景节点；⑥主动询问是否需要 drawio 架构图（是则另委 drawio-worker，prompt 必含 drawio-reference）。

协作关系

组成五元 = skill-architecture-judgment + agent-architect-worker + instr-architecture-behavior + command-arch + gate_architecture.py；依赖 opencode.jsonc agent 段（architect-worker 定义）与 config-main（instructions 数组引用 architecture-behavior.md）；与架构图委派链路（drawio-worker + drawio-reference）、kb-construction（内容交付型/上下文注入型）协作；知识图谱为母库离线资产（0910-软件工程架构方法论），不联网即可用。
