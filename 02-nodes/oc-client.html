⑤ 为什么存在（why）

设计意图（官方）

面向 app/web 前端生成类型安全的 HTTP 客户端，并通过协议层复用服务端同款端点契约；强调不得反向依赖 core/server（src/effect.ts:1-2），保持客户端纯净。

改造关联

本机未直接引用 client（本机界面是终端 CLI + 浏览器，不使用 app/web 前端与 client 包），属官方底座；但 client 与 sdk 同源（协议生成），本机若未来走 HTTP 集成可无成本接入同一契约。

⑥ 怎么用（how）

怎么用

· 入口：src/index.ts:1-2 re-export generated/index 与 OpenCodeEvent 类型；src/effect.ts 提供 Effect 原生客户端。package.json exports：'.'（Promise 版，src/index.ts）与 './effect'（Effect 版）。
· 生成制：由 @opencode-ai/server/api 经 httpapi-codegen 生成 src/generated/*（client.ts/types.ts/client-error.ts/index.ts）；README.md:8-12 要求改契约后 bun run generate + check:generated 防漂移。
· 用法示例（client/README.md:29-38）：import { OpenCode } from '@opencode-ai/client/effect'，OpenCode.make({baseUrl}) 后 client.sessions.create/prompt 直接用 canonical 类型（Session.ID/Location.Ref/Prompt）。

典型场景与协作

client 面向 app/web/session-ui 前端生成类型安全 HTTP 客户端：零 Effect 依赖的 Promise 根（无 core/server 依赖），/effect 子路径依赖 Effect+Schema+Protocol 且浏览器打包安全。协议层复用服务端同款端点契约，前端因此获得与 server 完全一致的端点类型；sdk-next/app/session-ui 三个官方包依赖它（official-dag reverse）。
