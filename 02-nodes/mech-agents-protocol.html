⑤ 为什么存在（why）

历史引入动机

为解决单 Agent 上下文爆炸与执行者模式问题，设定'调度者非执行者'分工：主 Agent 只编排(拆解/匹配/委派/聚合)，子 Agent 只执行，角色优先匹配 agency-agents。

当前需求驱动

复杂/多步/联网任务经由 task() 委派子 Agent 并行或接力，主 Agent 上下文不爆；对垂直领域(RL/LLM 推理等)search-agents 命中率低时改走 general 子 Agent+自写角色提示词，保证任意任务都可委派且有正确角色激活。

⑥ 怎么用（how）

触发方式

收到请求先分类判断：是否需要≥2 个工具/联网/多步推理→ YES 则第一条工具调用必须是 search-agents。

工作流/用法

①search-agents -Query 关键词 -Top 5 搜角色(只看 JSON 元数据)或自写 2-3 句角色提示词；②拆解任务：独立→并行 Task，有依赖→串行接力(data 传递)，耦合→单 Agent；③组装子 Agent prompt(SUBAGENT 身份+Role Activation+Skills to Load+Task+No Self-Assessment+Return Format)，drawio-worker 须精确写 drawio-reference；④聚合：success→summary|partial→+errors|failed→询问用户；⑤超 3 分钟没发 task→默念失败模式自查(执行者/例外滥用/假并行)。

协作关系

依赖 skill/agency-agents/search-agents.py 与 agent-index.json；主 Agent prompt 来自 opencode.jsonc agent.plan/build.prompt 内 Agent Protocol 与 instructions/agent-protocol.md；子 Agent 角色定义在 opencode.jsonc agent(plan/build/pdf-worker/drawio-worker/vision-worker/general/explore/reflection-worker/search-worker)；opencode.jsonc plan.permission 限制 bash 默认 deny。
