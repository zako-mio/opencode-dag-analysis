console-support

oc-console-support · package · G16-Console · Layer 2

① 作用

面向支持/客服的内部工具站（SolidStart SSR）。核心功能是用户数据 lookup：src/lib/lookup.ts 按 wrk_/key_/sk-/email 标识查询 workspace、billing、usage、订阅与禁用模型等全量数据，src/routes/lookup.tsx 展示查询结果，src/routes/index.tsx 提供查询表单。全部逻辑直接复用 console-core 的 schema 与 domain。

② 提供能力

· 按 email/workspace id/API key 查询用户全量数据（src/lib/lookup.ts:41）
· workspace 详情：users/billing/go/payments/usage/disabledModels 分节（src/lib/lookup.ts:30）
· 查询表单与结果展示页面（src/routes/index.tsx、src/routes/lookup.tsx）
· 复用 console-core 数据库 schema 与 Black/Lite/Subscription 领域逻辑

⑤ 为什么存在（why）

设计意图（官方）

支持后台与用户前台（console-app）同构（同 SolidStart + console-core），但只暴露 lookup 只读查询——刻意最小化支持工具面；use server + console-core 复用保证查询与前台一致（同一 drizzle schema、同一 Actor 隔离），支持人员无法直接改库。

改造关联

本机未改。装配层无对应物（客服功能未自建），仅作官方架构参考：最小只读支持后台 + 复用业务 core。

⑥ 怎么用（how）

怎么用

SolidStart 客服/后台站点：bun dev = sst shell --stage production -- vite dev（直连生产环境跑本地 dev）；routes/ 仅 index.tsx 与 lookup.tsx 两个页面，src/lib/lookup.ts 用 use server 直接调 console-core 的 drizzle 查询（Auth/User/Workspace/Billing/Payment/Usage/Key/Model 表联查）按 identifier 反查用户/workspace 全量快照。

典型场景与协作

支持人员用的用户/工作区查找后台：输入邮箱或标识符 → 返回该账号下所有 workspaces（auth、用户、billing、go 计划、支付、用量、禁用模型）。
