⑤ 为什么存在（why）

历史引入动机

完全自创（无上游），2026-07-04 创建（早于 8 月改造周期），2026-08-05 重大优化。初始动机：简历投递全流程自动化——投简历（浏览器打开招聘页+记录跟踪表）、识别简历（扫描表单字段+匹配信息库）、飞书表格双向同步。0804-recruit优化报告记载：京东校招投递（campus.jd.com）执行严重卡壳（浏览器脚本试错 4+ 次、行定位误判、row 追加失败），用户反馈"执行过程很卡壳，反思总结经验然后计划优化原 skill"，据此新增 tracker_writer.py 一体化脚本（JSON 输入→备份→定位→写入→打包→全量验证→失败回滚）并修正 SKILL.md 三处错误。0805 又发生简历跟踪上传事故（京东数据误写 row 774 导致 737 空行污染飞书），再修正则+游标定位。0802-opencode改造盘点报告认定其为"完全自创"。

当前需求驱动

求职季投递主场景：投简历、跟踪企业、飞书同步持续使用；browser-harness（CDP 浏览器自动化）与 tracker_writer.py 组成的投递管线是当前求职流程核心工具（0815-opencode-dsh桥接将其收入 exec-recruit 特设 preset 与 browser-harness 搭配）。

⑥ 怎么用（how）

触发方式

触发关键词：投简历、识别简历、更新信息库、记录投递、跟踪企业、招聘、简历投递、上传简历跟踪、下载简历跟踪、提取表单；或显式 /recruit-assist（0815 起为 user-invocable 手势）。

工作流/用法

· 投简历：启动 Chrome 远程调试（chrome-debug.ps1）→ browser-harness CDP 打开招聘页 → tracker_writer.py add 写入投递跟踪表
· 识别简历/更新信息库/记录投递/跟踪企业：表单字段扫描（JS IIFE 提取）匹配信息库
· 飞书同步：sync_feishu.py 增量上传/全量下载（.sync_state.json 状态机），上传/下载简历跟踪

协作关系

依赖 browser-harness skill（CDP 浏览器自动化）；与 resume-builder/soe-resume 构成简历求职 skill 群（0815 起共同收入 exec-recruit preset）；Excel 跟踪表/飞书表格为外部数据源
