skill-openspec-apply-change · skill · A6l-工作流 · Layer 1

① 作用

执行 OpenSpec 变更中 tasks.md 的实现任务，逐条完成并打勾。通过 openspec status 与 instructions apply 获取上下文文件、进度与任务列表，处理 blocked/all_done 状态。

② 提供能力

· 变更选择与状态解析（schemaName/planningHome/actionContext）
· apply 指令获取（contextFiles/进度/任务列表）
· 任务逐条执行与勾选
· blocked 状态引导转 continue-change
· store 感知（--store 标志）

⑤ 为什么存在（why）

历史引入动机

2026-08-04 随 Superpower 安装引入（OpenSpec 上游，author openspec）。spec-driven 工作流的实施端：tasks.md 就绪后逐条完成实现任务并打勾。引入动机：OpenSpec 强调"先同意要构建什么再写代码"，apply 是锁定规格后的编码执行器，通过 openspec instructions apply 获取 contextFiles/进度/任务列表，处理 blocked/all_done 状态。

当前需求驱动

所有 OpenSpec 变更的实施环节（specs 锁定后进入编码）；与 propose/ff 配对构成完整闭环；本地装配层代码改动若走 OpenSpec 流程即经此实施。

⑥ 怎么用（how）

触发方式

tasks.md 就绪开始编码时（description 触发词"实现任务""打勾"）；或显式 /openspec-apply-change；被 propose/ff 完成后提示接续。

工作流/用法

· 选择变更并解析 status（schemaName/planningHome/actionContext）
· 获取 apply 指令（contextFiles/任务列表/进度/动态指令），blocked 状态转 continue-change，all_done 建议归档
· 逐条实现任务并打勾，遵守 context 项目约束与 operationGuidance 建议

协作关系

上游衔接 propose/ff/new-change；blocked 时转 continue-change；完成后转 verify-change 验证、archive-change 归档
