验证与证据/从磁盘读不依赖对话记忆/路径本地化/元数据不入输出

② 提供能力

暂无

节点机制证据

④ 被依赖（下游）

无下游依赖

⑤ 为什么存在（why）

历史引入动机

为建立跨 Skill/Workflow 边界的通用编码准则，覆盖所有 Agent，防止依赖对话记忆的旧结果和跨机器绝对路径假设。

当前需求驱动

当前准则：验证与证据(不报告成功除非有新鲜验证证据，完成前跑测试→lint→报告)；从磁盘读取不依赖对话记忆(创建/修改文件前重新读依赖文件)；路径本地化(文件路径保持仓库本地化，子 Agent 返回绝对路径主 Agent 转相对路径)；元数据不入输出(context/rules/project_context 是约束不可复入产出文件)。

⑥ 怎么用（how）

触发方式

任何 Agent 实施代码/生成 DAG 工件时持续生效：声明完成前、创建/修改文件前必须磁盘重读。

工作流/用法

①完成声明前运行验证(测试通过→lint 通过→报告结果)并展示输出；②创建/修改文件前从磁盘重新读依赖文件；③DAG 工件生成写新工件前 read 所有 requires 依赖；④文件路径用相对路径或 repoRoot 拼接；⑤不以 context/rules 等约束字段入产出文件。

协作关系

指令源 instructions/auto-mode.md『Universal Coding Discipline』；与子 Agent 规则(mech-subagent-rules)、编码安全(mech-coding-safety)协作；影响 DAG 生成流程(proposal/specs/design/tasks requires 依赖读取)。
