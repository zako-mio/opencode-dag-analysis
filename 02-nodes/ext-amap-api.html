⑤ 为什么存在（why）

为什么需要

地理/LBS 能力：POI 搜索、周边搜索、路径规划、地理编码、旅游规划。解决 Agent 处理地点/路线/导航类查询需求；无它则无法回答附近美食/两地路线/地点坐标类任务。被依赖方：amap-lbs-skill（网页链接，不耗配额）、amap-budget-control（MCP API 用量预算）、amap-mcp-wrapper（MCP 入口）。

当前状态

双轨合理：amap-lbs-skill 优先生成免费网页链接（www.amap.com/search?query=、amap.com/dir 等，不消耗 API 配额），结构化数据才走 restapi.amap.com Web 服务（v5/place/text 等）——配额友好；amap MCP（npx amap-mcp-server@latest）因仅 2 工具 ~2000 tokens 极低用已在 opencode.jsonc 中 enabled:false（MCP 精兵策略），靠 skill 层满足日常。

⑥ 怎么用（how）

怎么接入

Web Service Key：环境变量 AMAP_WEBSERVICE_KEY（旧 AMAP_KEY 已废弃但兼容），或 config.json 本地持久化（chmod 600）；端点：https://restapi.amap.com/v5/place/text（POI，参数 key/keywords/region）、v3/direction/walking（步行路径）、v3/geocode/geo（地理编码）；埋点 https://restapi.amap.com/v3/log/init；MCP wrapper：amap-mcp-wrapper.ps1 设 $env:AMAP_KEY 后 npx -y amap-mcp-server@latest。

装配层调用

amap-lbs-skill 场景路由：场景一直接拼 www.amap.com/search 链接；场景二先 v3/geocode/geo 取坐标再拼带坐标链接；POI 详情/路径走 scripts/poi-search.js / route-planning.js（node 调用 index.js 的 searchPOI/walkingRoute，axios GET restapi.amap.com）；预算控制由 amap-budget-control skill 记录调用量与 5000 次/日预警。
