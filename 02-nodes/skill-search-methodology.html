⑤ 为什么存在（why）

历史引入动机

0905 联网搜索能力架构缺口清单——「无搜索方法论 Skill」，方法论此前散落 MEMORY 跨会话不稳。复用 anysearch Skill 编码范式 + goose frontmatter 懒加载，将搜索 SOP 沉淀为可加载的细粒度 skill。

当前需求驱动

需求驱动：需要一套结构化的搜索执行引擎（决策树路由 + 发现层三层 + Query 转译 + 证据包契约），把「搜索」从主Agent 的临时行为升级为可复用、可内化、可自扩展的能力。

⑥ 怎么用（how）

触发方式

search-worker 或主Agent 加载（Skills to Load 中指定）。前端 name/description 常驻，全量内容按需注入；命中 Trigger 条件（依赖外部事实/需交叉验证/实体歧义/时效超截止/用户要求搜索）即触发。

工作流/用法

①决策树路由判定 Path1/Path2/HYBRID/Path3；②发现层：LLM初发现（仅稳定知识）→ 信息源信用地图（渐进披露 domains/<域>.md）→ 外部搜索降级链（Tavily 首筛→必应/DDG/Wiki 零成本→agent-browser 动态兜底，带 Tavily 预算状态机与降级策略）；③Query 转译（实体消歧：中文词→拉丁学名+科名+排除运算符）；④回源与交叉验证（curl→agent-browser→API，≥2 独立源）；⑤输出证据包契约并按 validate_evpack.py 自检提交。

协作关系

由 search-worker 作为执行载体；受 search-behavior instruction 约束（信源分级/实证规则）；Path3 时联动 login-auth-channel skill（登录态）；依赖 source_credibility_map.md + domains/*.md（信源导航）、validate_evpack.py（证据包校验）、Tavily API + agent-browser + browser-harness（获取后端）、opencode.env（key 注入）、代理纪律。
