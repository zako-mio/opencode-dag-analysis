⑤ 为什么存在（why）

为什么需要

主模型供给：plan=deepseek-v4-pro（规划/委派推理）、build 与全部 7 个子Agent=deepseek-v4-flash（执行降本）都走 DeepSeek。解决本地要有强推理 + 低成本可商用模型的需求；无它则 opencode 无模型可跑，整个装配层（调度/委派/留档/反思）全部失效。

当前状态

合理：opencode.jsonc 以 provider.deepseek 配置 @ai-sdk/deepseek + baseURL https://api.deepseek.com/v1，model 分 pro(0.435/0.87 刀) 与 flash(0.14/0.28 刀) 两档，daily/deep variant 分别限 max_tokens 8192/16384 + reasoning_effort high/max——与 auto-mode 门控的决策边界表严格对应；缓存前缀策略（auto-mode.md 静态置前、动态置后）就是为 DeepSeek prefix-cache 98-99% 命中设计的。

⑥ 怎么用（how）

怎么接入

环境变量 DEEPSEEK_API_KEY（用户级已 setx，进程内不落盘）；API 端点 https://api.deepseek.com/v1/chat/completions（OpenAI 兼容）；opencode.jsonc 中 provider.deepseek.npm=@ai-sdk/deepseek + options.baseURL/timeout(300s)/headerTimeout/chunkTimeout；模型 modalities（pro 支持 image 输入、flash 仅 text）+ interleaved.reasoning_content 字段解析推理链。

装配层调用

opencode 主进程按 agent 配置选模型：plan 回落到顶层 model（deepseek-v4-pro），build/子Agent 显式 model=deepseek-v4-flash；variant daily/deep 切换 max_tokens 与 reasoning_effort；MEMORY.md 经 instructions 注入系统提示前缀共享缓存。
