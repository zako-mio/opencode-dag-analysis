⑤ 为什么存在（why）

历史引入动机

源自 0910-软件工程架构方法论知识图谱交付（167 节点/360 边/18 组/11 域/三层）；0911 opencode 架构能力扩展实战中由「速查 + 路径路由」升级为 Agent 可执行工作流能力包（workflow/checklist/templates/schemas/gate/openspec 集成）。

当前需求驱动

需求驱动：把一个架构问题变成可解释、可复核、可交付的产物——先判决策类型再路由节点，最后产 ADR（必选）与多维权衡矩阵（选型场景），并过机检门控方可交付；内置离线图谱不联网可用，知识分层引用纪律防止技术层过度推荐。

⑥ 怎么用（how）

触发方式

①自动路由：任务涉及技术选型/架构风格/模块与服务边界/架构评审/质量属性权衡/技术债治理/演进治理时，主流程自动加载；②显式命令 /arch；③openspec design 工件生成或修改时由行为层 architecture-behavior.md 强制触发。

工作流/用法

①判类型：归入 routing.md 的 18 个任务场景之一；②读速查：用 cheatsheet.md 对应层条目做首轮判断得到支撑节点 id；③深链接：按 11-node-pages/<ID>.html 或 15-md/nodes/<ID>.md 读节点全文确认；④产出+自检：按 schemas/adr.schema.json 产 ADR（选型加矩阵），边界走 boundary schema，均以 gate_architecture.py --kind adr|boundary 自检，不过不得交付；TEC 节点仅写入 standards_refs。

协作关系

由 architect-worker 作为执行载体；受 instr-architecture-behavior 行为层约束；配套 workflow.md / checklist.md / templates / schemas / gate_architecture.py / integrations/openspec-design.md；权威源在 0910 任务仓 20-agent-skill（install-skill.py 派生安装）；与 command-arch、kb-construction（内容交付型/上下文注入型）协作。
