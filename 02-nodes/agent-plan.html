⑤ 为什么存在（why）

历史引入动机

0801 P0 输入缓存优化引入：grill-me 协议固化到 plan prompt 开头（+500 tokens，缓存命中后免费）；0802 Mission留档系统：注入 Mission留档规则（5段报告+三重门控）；0803 改进落地：Return Format 升级为 8 字段 + MEMORY.md 同步询问；0803 Drawio 缓存修正：确认 agent.prompt 位于系统提示词位置 0，仅用于结构性协议替换；0805 Reflection 系统：新增 Build 末尾 pending.json 4 层封装写入 + Reflection 自检规则；0806 plan/build 双双降级 Flash（临时）；0807 /reflection 原生命令 prompt 同步；0813 plan 回滚 Pro（删除 plan.model 字段回落顶层 model，只动顶层一处省维护）。permission 对 bash 全 deny，仅放行 git status/git diff/Get-ChildItem 只读命令（L2 收紧执行面）。

当前需求驱动

调度者角色固定：plan=Pro（0813 回滚，规划/委派调度需 Pro 推理质量）、build=Flash（执行者降本）——分工清晰的模型策略；删 model 字段回落顶层实现单点维护；prompt 同时承载 Grill-Me + Agent 调度协议 + 编码安全 + 留档 + Variant 继承 + Reflection 规则，是全配置最大的定制项。

⑥ 怎么用（how）

触发方式

1) Grill-Me 协议：用 question 工具逐条追问收敛设计树，含 drift guardrails（一条消息必须以 question 调用结尾）+ 决策树收敛审计；2) Agent 调度协议 5 步：分类判断→search-agents.ps1 搜索角色→拆解任务（独立并行/依赖接力）→组装子Agent prompt（SUBAGENT 身份+Return Format JSON）→聚合（success/partial/failed）；3) MCP 路由决策：PDF→pdf-worker、图表→drawio-worker（必须精确写入 drawio-reference）、其他→general/explore；4) Variant 继承：收敛摘要带 [COMPLEXITY: X/20] 标记；5) Reflection 自检：waiting_count>0 则委派 reflection-worker。

工作流/用法

每次用户对话启动（Plan 模式）、复杂任务拆解与委派、Grill-Me 需求澄清、Mission 留档触发、Reflection 异步处理。

协作关系

build（执行收敛结果）、7 子Agent（委派）、agency-agents skill（search-agents.ps1 角色搜索）、reflection-worker（异步反思）、command-reflection（/reflection）。
