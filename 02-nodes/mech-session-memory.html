⑤ 为什么存在（why）

历史引入动机

0902 后新增：为应对会话上下文膨胀触发 compaction，建立阶梯式压缩决策树(L1 剪枝/L2 结构化压缩/L3 兜底摘要)，避免上下文爆仓与不必要的 compaction 触发。

当前需求驱动

当前压缩模板 5 段(当前状态/关键文件/已做决策/待解决问题/经验教训)，分别服务于恢复会话定位卡点、避免重复探索、不重问已决策项、知道待修问题、不踩两次坑；compaction 后保留 tail_turns=4(preserve_recent_tokens=16384)；模板不重复记录已截断的工具输出；模板语言与会话语言一致。

⑥ 怎么用（how）

触发方式

compaction 触发时；L1 剪枝(标记/截断超大工具输出)仍不足时进入 L2 结构化压缩。

工作流/用法

①L1 剪枝：截断超大工具输出仅留关键部分+位置标记；②仍不足→L2 按 5 段模板输出结构化记忆；③L2 也不足→L3 通用全量摘要兜底；④compaction 后保留 tail_turns=4；⑤不重复记录已裁剪输出，模板语言跟随会话语言。

协作关系

指令源 instructions/auto-mode.md『Session Memory 结构化压缩模板』与 MEMORY.md cycle_0818_v4；配置体现于 opencode.jsonc compaction(auto/prune/tail_turns=4/preserve_recent_tokens=16384/reserved=10000)；与输出控制(mech-output L1 剪枝)和编码纪律(mech-coding-discipline)协作。
