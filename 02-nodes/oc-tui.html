tui

oc-tui · package · G8-终端UI · Layer 3

① 作用

终端 UI 应用。src/index.tsx:1 导出 run/TuiInput；src/app.tsx:1-50 用 @opentui/solid 渲染整棵组件树（SDK/Data/Location/Theme/Clipboard 等 Provider 与 Session 路由），构建在 @opencode-ai/sdk/v2 客户端之上（src/context/sdk.tsx:1）。src/plugin/runtime.tsx 加载 @opencode-ai/plugin/tui 插件，feature-plugins/ 内含 diff-viewer/notifications/which-key/sidebar 等内置插件（src/feature-plugins/builtins.ts:1）。

② 提供能力

· 终端渲染运行时（src/app.tsx:1，基于 @opentui/solid）
· 会话交互 UI：输入/补全/历史/frecency（src/component/prompt/*）
· 对话框系统：模型/agent/主题/会话列表等 20+（src/component/dialog-*.tsx）
· 内置 TUI 插件：diff-viewer/通知/which-key/侧栏（src/feature-plugins/builtins.ts）
· 多 Context Provider：sdk/data/sync/theme/clipboard（src/context/*）
· V2 SDK 数据层接入（src/context/data.tsx、sdk.tsx）

⑤ 为什么存在（why）

设计意图（官方）

将终端交互封装为独立可复用包，经 opencode 的 cli/tui/layer.ts 加载，同时支持 TUI 插件扩展（@opencode-ai/plugin/tui），使 CLI 与桌面端共用交互逻辑。

改造关联

本机未直接修改 tui（本机主 Agent 以 CLI 非交互/自动化方式运行，未挂载自定义 TUI 插件），属官方底座；vision 插件只处理 chat.messages.transform，不涉及 TUI 渲染面，装配层没有对 tui 的引用点。

⑥ 怎么用（how）

怎么用

· 入口：src/index.tsx:1 —— export { run, type TuiInput } from './app'；src/app.tsx:1-15 用 @opentui/solid 的 render/useRenderer + @opentui/keymap 构建终端渲染循环，import @opencode-ai/core 的 Global/Flag/InstallationVersion 做运行状态。
· 36 个深路径导出（package.json exports）：./builtins、./config（keybind）、./context/*（args/epilogue/exit/kv/project/runtime/sdk/sync/theme/editor/clipboard）、./attention、./editor、./plugin/runtime、./plugin/slots、./ui/dialog、./ui/spinner、./ui/toast、./keymap 等，供宿主与 TUI 插件按需加载。
· 加载方式：被 opencode 的 cli/tui 命令（src/cli/cmd/tui.ts）与 cli/tui/layer.ts 动态加载；TUI 插件经 @opencode-ai/plugin/tui 的类型面挂 UI 插槽（plugin/src/tui.ts 的 Renderable/SlotMode）。

典型场景与协作

tui 是终端交互层：opencode 主程序加载它渲染会话/输入/工具状态 UI，TUI 插件经 plugin/tui 暴露的 slot 注入自定义组件（报告-01 插件钩子的一部分）；与 core 协作读全局状态（Global/Flag），与 sdk 协作连后端。claude-code 式交互、桌面端复用同一交互逻辑（cli 与 desktop 共用）。
