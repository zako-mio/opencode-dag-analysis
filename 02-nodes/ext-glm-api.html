⑤ 为什么存在（why）

为什么需要

补 DeepSeek-flash 无视觉能力的短板：read.ts 工具把图片文件经 GLM-4V 转文字描述（DeepSeek 纯文本模型才能理解）；vision-interceptor.js 插件在 chat.message 与 experimental.chat.messages.transform 钩子把用户上传图片替换为 VLM 描述文本，解决 does not support image input 报错。被依赖方：tools/read.ts、plugins/vision-interceptor.js，下游是 opencode 全部读图/图表校验流程（0807 起含 drawio 导出 PNG 的 VLM 校验）。

当前状态

合理但有过改动史：0807 修复前 glm-4.6v-flash（免费）高峰 429，改为付费 glm-4.6v 优先、429 降级免费 flash 的双模型链；Key 硬编码回退到环境变量 ZHIPU_API_KEY（用户级已 setx），避免明文泄露；插件侧用 Map 缓存 URL→描述防止历史消息重复计费。2026-08 仍为唯一视觉通道。

⑥ 怎么用（how）

怎么接入

环境变量 ZHIPU_API_KEY；端点 POST https://open.bigmodel.cn/api/paas/v4/chat/completions，Header Authorization: Bearer <key>，body: {model:glm-4.6v 或 glm-4.6v-flash, messages:[{role:user, content:[{type:image_url, image_url:{url: 图片URL 或 data:image/png;base64,...}}, {type:text, text:描述提示词}]}], max_tokens:4096, temperature:0.3}；响应取 choices[0].message.content。

装配层调用

read.ts 的 describeImage()：Bun.file→base64→按扩展名映射 mime→付费优先降级循环→返回描述文本；vision-interceptor.js 的 transformParts()：识别 part.type=file 且 mime 以 image/ 开头→调 describeImage→替换为 synthetic text part，并写日志 vision-int.log 记录 FIRED/SKIP/VLM OK 计数。
