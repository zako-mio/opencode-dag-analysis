⑤ 为什么存在（why）

历史引入动机

0802 盘点标注开源+改造，上游 RobMitt/grill-me-skill（171 星，基于 Matt Pocock 作品 MIT），原为 Claude Code（AskUserQuestion tool），改造为独立 opencode skill。0802-P0 任务（输入缓存优化）将其固化进 plan/build agent prompt 开头（+500 tokens，缓存后免费），从负收益变正。引入动机：Plan 阶段对用户的模糊需求逐条追问收敛决策树，防止拍脑袋决策。0802-Mission留档系统/后期改造.md 记录一次关键修复：原两段式协议（先 [GRILL] 文字再 question 工具）制造天然断裂点，多次出现 question 工具被跳过故障，改造为一段式（[GRILL] ack + question 同消息）。0807-opencode原理分析确认 plan/build prompt 经 agent.prompt 注入完全替换内置模板。

当前需求驱动

Plan 模式决策收敛的核心协议：0817-opencode-dag 收敛 13 项决策、0817-github-dag 收敛 12 项、0816-plugin-dag 6 项、0806-网申扩展v2 21 轮决策拆解、0807-华洋达面试复盘 27 轮结构化拷问等几乎所有 Mission 任务 Plan 阶段都在用。三层防漂移护栏（one-message rule / pre-output gate / convergence audit）保证长会话协议不退化。

⑥ 怎么用（how）

触发方式

用户说 grill me / 拷问我 / 面试我的方案 / 压力测试这个方案 时激活（SKILL.md description）；或 Plan 模式自动进入（plan prompt 内嵌协议）。

工作流/用法

1) 用 question 工具一次一问（2-4 个多选选项 + Other 自定义），输出 [GRILL] ack（1-2 句）+ question 必须在同一消息；2) 能查代码库的答案自己查，不问用户；3) 逐分支解析决策树直到所有决策依赖解析；4) 收敛时输出 [GRILL] Decision tree resolved. + 一句话总结 + 决策编号列表。

协作关系

与 plan/build 主Agent（prompt 内嵌，agent.prompt 注入）、question 工具（opencode 原生，UTF-8 支持中文）、Mission 留档系统（决策清单实时落盘）、plan-grill（dsh 侧映射 ask_user_question）协作。
