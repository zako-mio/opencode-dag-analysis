ui

oc-ui · package · G9-UI组件 · Layer 0

① 作用

SolidJS UI 组件库。src/components/ 含 50+ 基础组件（button/avatar/dialog/context-menu/diff-changes/icon 等，每个 .tsx 配套 .css 与 .stories.tsx），基于 @kobalte/core 无障碍原语；exports 将 ./components/*.tsx 直接映射为组件子路径（package.json:37）。同时提供 hooks（use-filtered-list）、context（dialog/file/i18n/marked/worker-pool）、theme 主题系统、i18n 词典、v2 新一代组件目录及 storybook 脚手架（src/storybook/scaffold.tsx）。

② 提供能力

· 50+ 基础 UI 组件（按钮/对话框/下拉/悬浮卡/图标等）
· Markdown 渲染管线（marked.tsx + worker-pool + shiki 流式高亮）
· Theme 主题解析与上下文（theme/index.ts、theme/context.tsx）
· i18n 多语言词典与 plural 规则（i18n/en.ts、context/i18n.tsx）
· File/Dialog/WorkerPool 等全局 context
· 图标集：provider/file/app 三类 sprite（provider-icons/types.ts 等）

⑤ 为什么存在（why）

设计意图（官方）

将跨 app/session-ui/enterprise 复用的无头基础组件与渲染原语独立成库，保证视觉一致性与按需导入（sideEffects 仅 css，package.json:14-16），同时承载 v2 新一代组件迁移（src/v2/）避免破坏旧接口。

改造关联

属官方底座，本机装配层未引用（无 agent/mcp/skill 依赖它）。但它是 DAG 中被依赖最多的 UI 节点之一（app/session-ui/enterprise/storybook/tui 均依赖），改造上游 UI 时是唯一公共修改点。

⑥ 怎么用（how）

怎么用

· 按组件子路径导入：package.json:35-57 exports 将 ./components/*.tsx、./context/*、./theme/*、./hooks、./v2/* 直接映射（如 @opencode-ai/ui/context/marked、@opencode-ai/ui/theme/context），app/enterprise/session-ui 均以该方式消费（enterprise/src/app.tsx:3-10 import Font/MarkedProvider/DialogProvider/I18nProvider/ui i18n dict）
· 主题与样式：@opencode-ai/ui/styles（tailwind 入口）、@opencode-ai/ui/theme（theme/index.ts:1 resolve/loader）、i18n 词典（i18n/en.ts:1 dict 导出，enterprise 用它做 SSR locale 检测 app.tsx:25-30）
· storybook 脚手架：./storybook/scaffold 与 ./storybook/fixtures 供组件开发预览（storybook/scaffold.tsx:30 create）

典型场景与协作

作为跨 app/session-ui/enterprise/storybook 复用的无头组件与渲染原语层：app 用 MarkedProvider+ThemeProvider 组装会话页；enterprise 用 ui 的 i18n/Font/对话框搭 SolidStart SSR 根；session-ui 用 ui 的 marked/worker-pool 实现流式 markdown。改一个基础组件（如 button）会同时影响所有上层包，是 UI 层最底层的公共依赖（G9-UI组件 Layer 0）。
