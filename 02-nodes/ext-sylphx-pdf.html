⑤ 为什么存在（why）

为什么需要

PDF 文档读取能力：简历解析、财报读取、论文提取。解决 Agent 无法直接读 PDF 二进制需求；无它则所有 PDF 类任务（招聘简历、学术文档）不可用。被依赖方：pdf-worker 子Agent（唯一工具源，permission 仅放行 pdf-reader_*）。

当前状态

合理：opencode.jsonc mcp.pdf-reader = {type:local, command:[npx, -y, @sylphx/pdf-reader-mcp@latest], enabled:true}——唯二启用的 MCP 之一（MCP 精兵策略 6 台仅留 2 台）；pdf-worker 固定 Flash + L3 最小权限（仅 pdf-reader_* allow），全局 deny 兜底；无文本层时走 pdf-ocr skill 路由 OCR。

⑥ 怎么用（how）

怎么接入

npx -y @sylphx/pdf-reader-mcp@latest 按需拉取（latest 随 npm 发布更新）；stdio MCP 协议；暴露 4 个工具（read_pdf 等文本提取类）；无需 API Key/环境变量（纯本地解析）。

装配层调用

pdf-worker 子Agent 经 pdf-reader_* 工具提取文本 → 返回 8 字段 JSON（status/summary/data/files_created 等）；MCP 路由规则保证 PDF 任务始终委派 pdf-worker 且不重复加载 pdf-ocr skill（省 token）；0707 简历任务用 explore 读 xlsx 而非 PDF 的案例证明路由按文件类型分流。
