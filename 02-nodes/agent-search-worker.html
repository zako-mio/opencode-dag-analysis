⑤ 为什么存在（why）

历史引入动机

0905 联网搜索能力架构落地时缺口清单最高优先级——「无独立搜索子Agent」，此前搜索被混入 general 子Agent，方法论散落 MEMORY 跨会话不稳。作为搜索执行层，只做发现+获取+交叉验证三段管线，不写报告。

当前需求驱动

需求驱动：需要实体消歧、多源事实核查、证据包构建等高价值搜索场景，由独立子Agent 承担可将方法论/后端退化链固化，且与主Agent 调度解耦（主Agent 只委派不执行）。

⑥ 怎么用（how）

触发方式

主Agent 在 plan/build prompt 的 MCP 路由中判定「需联网/多源核查/证据包」类任务时委派（Task 调用），模式=subagent，hidden=true，继承父会话模型。

工作流/用法

①主Agent 委派前注入【时间基线】今日= T 到 prompt 首行；②search-worker 加载 search-methodology skill 走决策树路由（Path1 通用/Path2 垂直域/HYBRID/Path3 登录态），执行 LLM初发现→信用地图导航→外部搜索降级链；③curl 静态→agent-browser 动态回源获取；④多源交叉验证/信源分级；⑤按证据包契约输出结构化 JSON（query/metas/cross_validation/gaps），提交前跑 validate_evpack.py 自动校验；⑥构造失败时降级标注「单一来源/blocked:true」，绝不编造。

协作关系

依赖 search-methodology skill（方法论与证据包契约）、search-behavior instruction（行为层强制）、login-auth-channel skill（Path3 命中需登录态时由主Agent 登录后重委派）、browser-harness/agent-browser（动态获取）、source_credibility_map.md（信源导航）、opencode.env（Tavily key）、代理纪律（境内直连/境外 7890）。
