⑤ 为什么存在（why）

为什么需要

协同办公主通道：recruit-assist 的飞书网申进度表同步（sync_feishu.py 增量上传/全量下载）、简历求职流程的表格/文档操作、日常日历/消息/云盘任务都需要。解决 Agent 能操作飞书全部业务域的需求；无它则简历投递跟踪表与办公文档无法程序化读写。被依赖方：skills/lark-suite（路由包装层）、recruit-assist、exec-recruit preset。

当前状态

合理：lark-cli v1.0.76（Go，MIT，上游 yjwong/lark-cli）本地安装，SKILL.md 强制 Step 0 先读 references/shared.md（认证检查/--as user|bot 身份/JSON 输出合约）；23 域中 20 个占位已在 0802 修复为 lark-cli skills read 动态加载；Windows 下必须 cmd /c 调用。仅 3 个手写 reference（drive/shared/sheets），其余按需拉官方内置 skill。

⑥ 怎么用（how）

怎么接入

lark-cli auth login --recommend（输出授权 URL，浏览器完成 OAuth，自动取 token；可 --no-wait + --device-code 轮询）；lark-cli config init --new 首次配 app credentials；调用形态 cmd /c "lark-cli <domain> +<shortcut> [flags]"，如 lark-cli drive +upload <本地路径> <folder_token>、lark-cli drive +download <file_token> <本地路径>；输出 JSON 信封 {ok, identity, data, meta}，成功判 ok==true 而非 code==0。

装配层调用

lark-suite skill 按意图路由表加载 references/<domain>.md → 按域指令执行 lark-cli shortcut → 解析 JSON；Fallback 链：lark-cli skills read lark-<domain> → lark-cli schema → lark-cli api GET/POST → WebFetch 官方文档；recruit-assist 的 sync_feishu.py 直接调 lark-cli 做表格同步。
