oc-core · package · G6-核心服务 · Layer 2

① 作用

核心服务层（无根 index.ts，按子路径导出，package.json:18-23 暴露 effect/layer-node、session/runner 等）。实现数据库（src/database/sqlite.ts，drizzle ORM）、会话执行（src/session/runner/index.ts:20-28 从已记录历史执行一次续跑）、配置解析（src/config/* 覆盖 agent/command/mcp/lsp/formatter）、权限策略（src/permission.ts）、事件流（src/event.ts，基于 PubSub/Queue）、文件系统与搜索（src/filesystem/*，含 ripgrep 封装 src/ripgrep.ts:5）。Effect 运行时层见 src/effect/layer-node.ts 与 app-node-builder.ts。

· 事件总线与持久化事件（packages/core/src/event.ts:3）

· Effect 服务层组装（packages/core/src/effect/layer-node.ts、app-node-builder.ts）
· Provider/Model/Catalog/集成认证 领域服务（packages/core/src/provider.ts、catalog.ts、integration.ts）

⑤ 为什么存在（why）

设计意图（官方）

把会话/存储/配置/权限等可复用领域逻辑从 CLI 与 HTTP 层抽离为纯 Effect 服务，供 opencode 主程序、server 包及测试直接注入依赖，实现平台无关的核心（bun/node 双实现见 package.json imports 的 #sqlite/#pty/#fff）。

改造关联

本机装配层经 config-main 深度改造 core 的运行行为：provider 走 @ai-sdk/deepseek 直连（core/provider 路由）、permission 三层纵深（core/permission 服务）、compaction 参数（core/session 的 compaction）、Reflection 系统的 pending.json 与指令加载；plan/build/explore/general 等 7 个 agent 全部依赖 provider/deepseek 经 core 的模型路由与权限服务。即 core 是被引用最多的官方底座（modified-dag 中 8 个节点依赖它）。

⑥ 怎么用（how）

怎么用

· 入口/导出：package.json exports 提供 ./effect/layer-node、./effect/app-node、./session/runner、./system-context 与 ./src/*.ts 通配；src/ 下 90+ 模块（session.ts/event.ts/config.ts/permission.ts/provider.ts/tool-output-store.ts/agent.ts 等）按路径导入。
· 关键服务装配：src/effect/layer-node.ts 提供 LayerNode（类型化依赖节点/group 装配），src/effect/app-node.ts 提供 GlobalNode/LocationNode 分类标签；src/session/runner/index.ts:25-33 导出 SessionRunner.Service（run: 从已记录 Session history 续跑一次）。
· 无 bin（bin 字段实为顶层 opencode 的声明）；被 opencode/server/tui/sdk-next/app/enterprise 等以 workspace 依赖方式直接 import 服务（如 server/src/routes.ts:3-11 批量 import LayerNode/Database/EventV2/SessionV2 等 10+ 服务）。

典型场景与协作

core 是产品的能力底座：server 包把它粘成 HTTP 服务（routes.ts 的 applicationServices = LayerNode.group([Database.node, EventV2.node, ...]）），opencode 主程序用它做会话/存储/权限/工具调度，tui 用它做全局状态与安装版本。与 llm 协作（tool-output-store.ts:11 import llm 类型）完成请求-工具循环，与 plugin 协作承载插件运行时，是报告-02 所述会话生命周期与消息处理的实际执行者。
