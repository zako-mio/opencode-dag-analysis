⑤ 为什么存在（why）

⑥ 怎么用（how）

触发方式

需要为 opencode 新增/补齐一项能力（架构/检索/图表/视觉等）、某能力只有单层而成为孤儿/半成品、opencode 自身 skill/agent/instructions/门控需批量治理时加载。

工作流/用法

①勘察（用五要素三层栈诊断孤儿/半成品）；②计划（分级介入强度，契约先行且 schema 由主Agent 亲写）；③阶段 0 前置修复（skill 双根统一迁移前备份、引用普查 grep 硬编码、stale 归档、能力注册表回填）；④阶段 1 MVP（skill 升级为可执行工作流 + 可见子Agent + 行为层全局强制 + /name 命令 + 独立 gate 脚本）；⑤单一真相源（占位符 + install 派生 + reconcile 逐字节对账，二次 apply 幂等）；⑥门控（字段级白名单判据 + 正负向自检 + 三合一冒烟）；⑦注册表闭环。

协作关系

以 architecture-judgment 三层栈为实战样例；与 opencode-config（能力注册表 local/capabilities.md）协作；与 architect-worker / architecture-behavior 同构；依赖 config-main。
