⑤ 为什么存在（why）

设计意图（官方）

将发布流程共用的版本决策逻辑从 CI 脚本中抽离为可 import 的库，保证多个发布任务（channel 判断、bump 语义）行为一致，是官方发布流水线的单一事实源。

改造关联

属官方底座，本机装配层未引用（本机不跑官方发布流水线）。官方依赖链：cli 的 devDependencies 引用 @opencode-ai/script（package.json:31）。

⑥ 怎么用（how）

怎么用

· exports "." → ./src/index.ts（package.json:12-14），作为发布脚本库被 cli 的 script/build.ts:3 import 使用（$ 从 bun、Script.version/channel 参与构建）
· src/index.ts:5-76 读取仓库根 package.json 校验 bun 版本（:16-18 semver.satisfies）、按 env/分支/registry 计算 channel（latest/preview，:26-32）与 version（含 +1 patch 逻辑，:34-48）、加载 .github/TEAM_MEMBERS 团队成员（:50-58）
· env 控制：OPENCODE_CHANNEL/OPENCODE_BUMP/OPENCODE_VERSION/OPENCODE_RELEASE（:20-25）

典型场景与协作

作为构建/发布共享工具库：cli 构建时用它算 channel/version 决定产物命名（script/build.ts:81 execArgv --user-agent lildax/{Script.version}），CI 流水线用它做 bump 语义与发布渠道决策。任何发布相关任务先经它统一版本决策，避免各脚本口径不一致。
