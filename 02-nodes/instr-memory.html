⑤ 为什么存在（why）

历史引入动机

0803 改进落地 P1（Claude Code 对比报告识别记忆系统差距）：当前会话结束后上下文丢失，无持久化记忆机制 → 创建 MEMORY.md（4 类分类 × 15 条预填充：中文偏好/安全规则/配置路径等）；Grill-Me 决策：路径 ~/.config/opencode/MEMORY.md（全局共享）、去掉子Agent next_step 字段、instructions 顺序 auto-mode.md 在前（保缓存）MEMORY.md 在后（动态内容）；0805 Reflection 系统：格式迁移 §-分段 Hermes 格式（保留 4 段分类作标签）+ 自引用规则（waiting_count 检查）+ /reflection 命令定义 + 容量上限 3500 提醒；0813 skill 更新：同步修正精兵策略口径（7→6 台 MCP、headroom MCP 禁用但 CLI 保留、压缩阶梯修正）。

当前需求驱动

全局共享版（~/.config/opencode/，workspace 根可建项目版共存）；放在 auto-mode.md 之后（动态内容不破坏静态前缀缓存断点）；§-分段格式上限 ~3500 字符（超限提示手动整理）；每次收到用户消息先查 meta.waiting_count>0 → 有 waiting 则标 processing 委派 reflection-worker（无论成败继续正常流程）。

⑥ 怎么用（how）

触发方式

经 config.instructions 数组第 2 位加载；§ 分段条目（日期+主题+要点，如'(2026-08-03) 编码安全：优先 edit 工具...'）；Reflection 自引用检查（任务分类前置）；/reflection 审阅后写入新 § 段落；任务完成后不再单独询问同步（统一走 /reflection）。

工作流/用法

每个会话加载（动态内容）；跨会话经验继承（历史决策/教训直接可用）；Reflection 触发检查（waiting_count 门控）。

协作关系

command-reflection（审阅写入）、agent-reflection/reflection-worker（产出条目）、config-main（instructions 引用）、instr-auto-mode（缓存序位）。
