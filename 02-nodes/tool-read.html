⑤ 为什么存在（why）

历史引入动机

早期用 Bun + TypeScript 重写 opencode 内置 read 工具（tools/read.ts）；0802 盘点：核心增强——图片自动分析（9 种格式调 GLM-4V 描述）、降级处理、目录列表（readdirSync）、文本分段（offset/limit）；同时指出 GLM API Key 硬编码安全问题（Line 15）；0803 编码安全修复时确认此为 custom read 工具（非内置）；0807 VLM 图片识别修复：付费 glm-4.6v 优先 + 429 降级免费 glm-4.6v-flash + Key 改环境变量（process.env.ZHIPU_API_KEY 优先 + 硬编码兜底）。

当前需求驱动

保留图片自动分析能力（IMAGE_EXTS 9 种格式）→ GLM-4V 描述；GLM_MODELS = ['glm-4.6v', 'glm-4.6v-flash'] 付费优先降级链；Key 环境变量化；与 vision-interceptor 构成双保险视觉链路（0807 报告定位）。

⑥ 怎么用（how）

触发方式

1) execute：existsSync → statSync 判断目录/文件；2) 目录 → readdirSync 列条目；3) 图片（extname 命中 IMAGE_EXTS）→ describeImage：Bun.file 读二进制 → Buffer base64 → data URL → tryVLM 循环 GLM_MODELS（付费 429 降级免费，非 429 直接报错）→ 包装为'[图片分析: 文件名]'+描述；4) 文本文件 → Bun.file.text() + offset/limit 分段（默认 2000 行）带行号输出。

工作流/用法

读本地图片文件（VLM 描述）、读大文件分段（>2000 行）、列目录条目。

协作关系

plugin-vision-interceptor（双通道视觉链路，read 通道结果不写入插件 processedImages 缓存）、GLM API（智谱视觉模型）。
