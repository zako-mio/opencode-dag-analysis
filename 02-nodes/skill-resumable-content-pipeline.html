⑤ 为什么存在（why）

历史引入动机

源自 2026-08-25 LLM 论文全集采集/全量分析、09-10 软件工程架构知识库、09-09 课程知识库等多轮大型内容生产实战，经合并批 batch_20260911 提炼。

当前需求驱动

需求驱动：目标产物由 ≥50 个同构节点组成、单会话无法一次完成、需多路并行子Agent 分片产出且超时/中断后零浪费恢复，多形态交付并通过多层门控。

⑥ 怎么用（how）

触发方式

任务涉及从零构建论文全集/课程知识库/方法论图谱等需多子Agent 分片、数小时级、可中断续跑的内容生产时加载；适用节点数多、耗时数小时、允许分阶段暂停续跑；不适用 <20 节点小任务或每节点需强交互确认场景。

工作流/用法

①契约先行落盘（contract.md：路径/命名/schema/信源分级/版权红线，长 prompt 委派引用短路径防 JSON 截断）；②骨架先行门控（先数据 JSON 层完成节点清单 + DAG 校验再并行写作）；③分片并行（按领域/主题/年代分片，子Agent 只写各自唯一文件域，预算约 20 token/s、单轮 <10min）；④幂等脚本先落盘（每节点独立目录，超时复跑不重复不丢）；⑤聚合终裁（主Agent 去重、统一口径，不取平均不重跑，双路补漏）；⑥独立门控（主Agent 不信生产者自检，查数据完整性/结构/HTML/链接可达性/内容有无，CI 不可用层显式 SKIPPED）；⑦发布与 git diff 漂移检测。

协作关系

与 kb-construction（内容交付型）、single-source-docs-pipeline（多产物一致）、search-methodology（信源）、drawio-worker（图表）协作；契约先行原则对齐 mech-coding-discipline；依赖 config-main。
