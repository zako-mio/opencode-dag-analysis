console-function

oc-console-function · package · G16-Console · Layer 2

① 作用

Cloudflare Workers 端边函数集：auth.ts 是 OpenAuth issuer（GitHub/Google 登录 + Cloudflare KV 存储，签发 account/user subject），log-processor.ts 是 tail 处理器，把 Zen/Go 网关的请求日志转发到 Honeycomb 与数据湖，stat.ts 提供 TPS 限流统计查询端点。src/auth.ts:44 用 @openauthjs/openauth 构建 OAuth issuer，src/log-processor.ts:5 解析 _metric: 前缀日志聚合指标。

② 提供能力

· OAuth 登录 issuer：GitHub/Google provider + Cloudflare KV 会话存储（src/auth.ts:44）
· Subjects 定义：account/user 两级认证主体（src/auth.ts:25）
· 网关日志采集：tail 事件 → Honeycomb batch + lake ingest（src/log-processor.ts:5）
· TPS 限流统计查询：按模型 id 聚合 30 分钟窗口 qualify/unqualify（src/stat.ts:7）

⑤ 为什么存在（why）

设计意图（官方）

把认证签发、限流计数查询、日志遥测拆成独立 Worker，与 app 的 SSR 路由解耦——auth 需要 KV 会话存储与 OAuth provider 配置，log-processor 需要 Trace API，放在 function 层可独立部署/独立扩缩容；console-core 的业务函数（Account/Workspace/Actor/Database）被直接 import 复用，保持单一业务源。

改造关联

本机未改；装配层没有直接复用 function 包，但其独立 Worker 做限流/遥测的架构与本地 headroom proxy（8787 端口压缩代理）、browser-harness daemon 的独立进程承载横切能力是同一设计思路。

⑥ 怎么用（how）

怎么用

Cloudflare Worker/Lambda 入口包：src/auth.ts 导出 fetch handler（@openauthjs/openauth issuer，GitHub/Google OAuth provider + CloudflareStorage KV 会话）；src/stat.ts 导出 POST / 查询 ModelTpsRateLimitTable 近 30 个 1 分钟 interval 的 qualify/unqualify 计数；src/log-processor.ts 导出 tail()（Cloudflare Workers Trace 日志处理：解析 _metric: 前缀日志 → 转发 Honeycomb https://api.honeycomb.io/1/batch/zen + 数据湖 ingest）。依赖 ai / @ai-sdk/anthropic|openai|openai-compatible（LLM 代理链）。

典型场景与协作

控制台的 Serverless 边缘函数：openauth 认证签发（account/user subjects）、TPS 限流计数聚合查询（配合 app 侧 modelTpsLimiter）、Zen 网关的 observability 数据管线（honeycomb 批量写入 + lake ingest，含 llm.error 事件）。
