⑤ 为什么存在（why）

设计意图（官方）

作为测试基础设施：让 LLM 请求与 HTTP 流量可确定性回放（VCR 模式），保证 CI 中测试不依赖网络与真实 token 计费；被 core/llm 的测试与开发流程引用。

改造关联

本机未直接引用 http-recorder（装配层不做 LLM 请求录制，成本优化走 DeepSeek prefix-cache 而非 VCR 回放），属官方底座；本机在测试/复现需求上以 config 级缓存（cache_read 0.003625）替代录制方案，二者是同一「降本/确定性」目标的不同路径。

⑥ 怎么用（how）

怎么用

· 入口：src/index.ts:1-11 —— export const HttpRecorder = { http, socket }（HTTP + WebSocket 双通道录制）；namespace 导出 CassetteMetadata/RecorderOptions/RedactOptions/RequestMatcher/RequestSnapshot 类型。
· 用法（README.md:8-21）：@effect/vitest 测试中把 HttpClientRequest 挂上 recorder 录制成 JSON cassette，测试时确定性回放（VCR 模式）；redaction.ts/redactor.ts 提供密钥/头脱敏。
· 依赖仅 @effect/platform-node(-shared)，Node 22+/Bun；核心文件 cassette.ts（cassette 读写）、matching.ts（请求匹配）、recorder.ts、socket.ts/websocket.ts。

典型场景与协作

http-recorder 是测试基础设施：llm 的 devDependency 引它（llm/package.json），使 LLM provider 请求（HTTP/WS 双通道）可录制回放，CI 中测试不依赖网络、不产生真实 token 计费；redact 机制保证录制文件不含密钥。core/llm 的开发与测试流程（报告-03 的请求链路分析依赖可复现请求）均受益。
