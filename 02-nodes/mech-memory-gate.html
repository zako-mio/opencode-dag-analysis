⑤ 为什么存在（why）

历史引入动机

2026-08-19 根因修复：此前直接改 MEMORY.md 导致内容漂移/无溯源，故设硬门禁禁止绕过反射链路直接写入，保证每条记忆带来源签名可回溯。

当前需求驱动

确保记忆写入仅经五步链路(①封装 4 层输入→②追加 pending.json status=waiting→③reflection-worker 处理→④用户 /reflection 逐条 yes/edit 确认→⑤确认后才写入)，写入的每个 § 段必须带 [src: <cycle_id>] 签名，无签名禁止写入，唯一例外是 /reflection 命令本身。

⑥ 怎么用（how）

触发方式

任何试图写入 MEMORY.md 的编辑/写操作会被拦截；唯一合法触发是 /reflection 用户确认；另子 Agent 若产出记忆条目写入 memory_pending/ 待审。

工作流/用法

①记忆产出方(主 Agent 封装 4 层或子 Agent 交 memory_pending/)不直接碰 MEMORY.md；②reflection-worker 分析并入 pending.json results(status=done)；③用户 /reflection 三池扫描+统一分析/逐条确认；④确认 yes/edit→主 Agent 写 MEMORY.md(§ 分段，带 [src: cycle_id])；⑤写后校验脚本按 § 切分每段首行为 [src:...]；⑥备份→原子写回→JSON 校验，容量>5000 走分层精简。

协作关系

目标文件 MEMORY.md(§-分段格式)；由 opencode.jsonc agent.plan/build.prompt 内 Memo 硬门禁段与 auto-mode.md『Universal SubAgent Rules』身份约束共同强制；依赖 Reflection 链路；子 Agent 记忆写入 ~/opencode/archive/Reflection/memory_pending/。
