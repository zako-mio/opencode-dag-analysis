⑤ 为什么存在（why）

设计意图（官方）

为组件库提供隔离的开发/审查环境，通过 mock 掉 app 的副作用 context 使跨包组件可以独立预览与回归测试，是 UI 开发流程的质量基础设施而非运行时依赖。

改造关联

属官方底座，本机装配层未引用（本机未启用 Storybook 工作流）。devDependencies 依赖 ui/session-ui（package.json:12-13），纯开发期工具不影响运行时。

⑥ 怎么用（how）

怎么用

· bun storybook（package.json:7 storybook dev -p 6006）本地组件浏览；bun build（:8 storybook build）产出静态组件文档
· 配置 .storybook/main.ts:13-29：storybook-solidjs-vite 框架 + addon（docs/a11y/vitest），stories glob 聚合 ../../ui、../../session-ui、../../app/src 三包 stories（main.ts:25-29）
· app context mock：main.ts:36-60 用 alias 将 @solidjs/router 与 15+ app context（local/file/prompt/layout/sdk/sync/command 等）替换为 mocks 目录实现，使 app 组件可独立渲染

典型场景与协作

作为组件开发与审查环境：ui/session-ui 的组件在隔离环境下预览回归，app 的页面级组件通过 mock 掉副作用 context（router/server/language）后在 Storybook 中独立渲染。典型协作：开发 ui 新组件→写 stories→storybook 预览→a11y/vitest addon 做可访问性与行为测试。
