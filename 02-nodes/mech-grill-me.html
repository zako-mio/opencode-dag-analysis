⑤ 为什么存在（why）

历史引入动机

源自 RobMitt/grill-me-skill(基于 Matt Pocock 作品 MIT)，用于对用户方案/设计进行压力测试，逐问题拷问直至设计意图完全对齐(Fork 自外部 skill 集成)。

当前需求驱动

作为 Plan 模式的默认协议被内联进 opencode.jsonc agent.plan.prompt/subagent 角色，确保正式编码前决策树所有分支被显式解析，避免模糊需求导致 Build 返工；在长会话中靠三层护栏防协议漂移。

⑥ 怎么用（how）

触发方式

用户关键词触发('grill me'/'拷问我'/'面试我的方案'/'压力测试这个方案')；或 Plan 模式启动时由 opencode.jsonc agent.plan/build.prompt 内联的 Grill-Me Protocol 自动启用。

工作流/用法

①收到方案后，每次回答后输出 [GRILL] 简短致谢 → 同一消息内紧接一次 question 工具调用(一次只问一个问题，2-4 个可选答案)；②能靠探索代码库/文件自行回答的分支就先自行探索而非问用户；③沿设计树走遍所有分支直至无决策依赖；④收敛时输出 [GRILL] Decision tree resolved. + 一句话总结 + 决策编号列表。

协作关系

依赖 opencode 原生 question 工具；指令源 skill/grill-me/SKILL.md；已内联于 opencode.jsonc agent.plan.prompt 与 agent.build.prompt；与 GATE 门控(Plan 收敛写 GATE+COMPLEXITY)与 Reflection 的 Layer A(GRILL 决策列表)协作。
