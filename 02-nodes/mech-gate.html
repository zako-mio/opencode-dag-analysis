⑤ 为什么存在（why）

历史引入动机

为解决任务复杂度与推理深度不匹配导致的长任务输出截断/多轮重试成本失控，引入强制自评门控：任务开始前先量化影响范围/逻辑深度/操作数量/风险以决定用哪档推理。

当前需求驱动

作为主 Agent(plan/build)的第一条强制输出，用 4 维各 1-5 分(影响范围/逻辑深度/操作数量/风险精度)求总分定 Variant(≤12→Daily，≥13→Deep)，评分保守宁高估，边界值 12→Daily、13→Deep，为成本与质量作显式权衡。

⑥ 怎么用（how）

触发方式

主 Agent 收到任务后、任何操作之前，第一条助手消息必须以 [GATE] 范围=X 深度=X 操作=X 风险=X → 总分=XX → Daily|Deep 开头；子 Agent 为纯执行者不输出 GATE。

工作流/用法

①按 4 维自评表逐一打分并求和；②查决策边界表定 Variant 与 max_tokens/reasoning_effort；③输出 GATE 行后继续任务；④Plan 收敛时把 GATE 自评+COMPLEXITY+决策列表封装进 Reflection Layer A；⑤Build 若检测到 [COMPLEXITY] 标记则继承推理深度不重评。
