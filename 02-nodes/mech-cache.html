⑤ 为什么存在（why）

历史引入动机

本项目 API 调用基于 DeepSeek prefix-cache 机制：缓存命中时 input token 成本降 98%~99%，前缀字节级变化会导致整个缓存失效，故把静态内容稳定置前以最大化命中。

当前需求驱动

作为成本优化核心纪律，要求所有文档/规则/工具定义等静态内容保持在 prompt 前缀且不改，动态内容(用户问题/检索结果/变化参数)始终放末尾；auto-mode.md 全 Agent 作为共享前缀加载，委派协议经 agent.plan/build.prompt 注入(方案 A prompt 隔离)。

⑥ 怎么用（how）

触发方式

持续作用于每次 API 调用设计：任何静态共享前缀内容必须字节稳定；缓存协议承诺本文档 session 运行期间不修改/不重排/不动态注入。

工作流/用法

①把共享前缀(如 auto-mode.md/协议)固定在 prompt 最前且冻结；②动态内容追加到尾部；③避免在同一前缀间插入时间戳/会话 ID/动态内容导致缓存失效；④MCP/Skill 工具 schema 首次加载后已被缓存，后续同类任务不做重复 tool discovery。

协作关系

作用于所有指令源：instructions/auto-mode.md『Cache Awareness』与『协议稳定性承诺』；与 Parallel & Batching(mech-parallel)及 Variant(mech-variant)协作；配置体现于 opencode.jsonc compaction 段。
