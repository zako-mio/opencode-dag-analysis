当前需求驱动

大型交付物/源码克隆（100+MB/数千文件）上传 GitHub 的标准流程：预检（README/LICENSE/敏感扫描）→ 代理登录 → git 初始化 → 嵌套 .git 处理 → 全量提交 → postBuffer 调优 → 推送与协作（权限 deny 转用户）→ 上传后验证清单；当前 DAG 交付物（plugin-dag/opencode-dag）上传 GitHub Pages 持续复用。

⑥ 怎么用（how）

触发方式

触发关键词：上传GitHub、GitHub上传、大仓库上传、gh repo create、git push、嵌套git、postBuffer、设备码登录；大型目录/交付物上传 GitHub 时。

工作流/用法

· 准备环境（安装 gh CLI、git 身份、预检 README/LICENSE/.gitignore + 敏感信息扫描）→ 代理登录（直连超时 HTTPS_PROXY=127.0.0.1:7890，设备码浏览器登录，gh auth status 先行）
· git init（main 分支）+ 断链修复 + 嵌套 .git 处理（git rm --cached + 删除内部 .git 后全量 add）
· 全量 commit → gh repo create --public --source --push → schannel 中断时 http.postBuffer 调优 → 权限 deny 时转用户手动 push → 验证 remote tree 条目数/README/topics

协作关系

与用户协作（权限 deny 时移交手动 push）；被 DAG 交付链引用（0816/0817 DAG 交付物上传）；吸收三个开源 skill 方法论
