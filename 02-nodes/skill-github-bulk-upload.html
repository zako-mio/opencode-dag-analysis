github-bulk-upload 装配层

skill-github-bulk-upload · skill · A6o-交付发布 · Layer 0

① 作用

GitHub 大仓库全量上传方法论。当任务涉及将大型交付物/源码克隆(100+MB/数千文件)上传至 GitHub 仓库、处理嵌套.git被识别为gitlink、大文件推送schannel中断、gh CLI代理登录、权限deny转手动push时使用。触发关键词：上传GitHub、GitHub上传、大仓库上传、gh repo create、git push、嵌

② 提供能力

暂无

③ 依赖（上游）

无内部依赖（或为叶子/外部）

④ 被依赖（下游）

无下游依赖

⑤ 为什么存在（why）

历史引入动机

源自 DeepSeek Harness 源码解析交付物上传实战（100+MB/8102 文件→公开仓 deepseek-harness-analysis，提交 b22d6bc，远程 tree 9336 条目）；吸收三个开源 skill 方法论（上传预检/敏感扫描/gh CLI 纪律），补足嵌套 .git、断链、postBuffer、代理登录、权限移交等本项目独有场景。

当前需求驱动

需求驱动：需将大型交付物/源码克隆全量上传 GitHub，处理 Windows 下嵌套 .git 被识别为 gitlink、schannel 中断、gh CLI 直连超时走代理设备码登录、push 被权限 deny 转用户手动，以及沙箱禁 push 时改用 Git Data API 整树推送。

⑥ 怎么用（how）

触发方式

任务涉及将 100+MB/数千文件交付物或源码克隆上传 GitHub、处理嵌套 .git/gitlink、大文件 schannel 中断、gh 代理登录、权限 deny、批量仓库上传时加载。

工作流/用法

10 步：①准备环境（装 gh CLI/git 身份/敏感扫描）；②代理登录（HTTPS_PROXY + 设备码，非交互须移交用户）；③git 初始化；④断链修复；⑤嵌套 .git 处理（git ls-files -s 查模式 160000→删嵌套 .git）；⑥全量提交；⑦gh repo create + topics；⑧postBuffer 调 500MB/HTTP1.1；⑨推送与协作（deny 转用户手动）；⑩验证（tree 条目/README 大小/branch/visibility/topics 实测，不凭返回 200 推断成功）。沙箱禁 push 时改走 Git Data API（blob→tree→commit→ref）。

协作关系

依赖 gh CLI 与 git（定向代理）；凭据按 L1/L2/L3 分层披露；与 single-source-docs-pipeline 分工（Contents API 单文件 vs Git Data API 整树）；依赖 config-main（permission 权限规则）。
