console-app

oc-console-app · package · G16-Console · Layer 2

① 作用

Console 主站前端（SolidStart/SSR + Nitro on Cloudflare），包含营销落地页、认证回调、workspace 管理（billing/keys/members/settings/usage）、Zen 与 Go 两个 LLM API 网关，以及到 docs/stats/bench 的代理路由。src/app.tsx 挂载路由与 i18n，src/routes/zen/v1/chat/completions.ts 走统一 handler 做鉴权/计费/限流后转发到上游 provider，src/lib/stats-proxy.ts 反向代理 stats.opencode.ai。

② 提供能力

· 营销/下载/企业页与多语言 i18n（20 语言，src/i18n/）
· OpenAuth 认证与 session 处理（src/routes/auth/、src/context/auth.ts）
· workspace 控制台：billing 充值、API key、成员、用量图表（src/routes/workspace/[id]/）
· Zen 网关：OpenAI/Anthropic/Google 兼容 API + key/IP 限流 + 用量计费（src/routes/zen/）
· Go 网关（轻量版 zen，src/routes/zen/go/）
· Stripe webhook、honeycomb webhook、enterprise lead 提交
· docs/stats/bench 站点反向代理（src/routes/docs/、src/routes/data/）

⑤ 为什么存在（why）

设计意图（官方）

控制台全部业务状态（workspace/billing/usage/limits）以 SSR + SolidStart 文件路由承载，前端不直接读写 DB，而是 import @opencode-ai/console-core 的 fn 函数（drizzle 查询 + Actor 上下文）在 server 端执行——单一业务逻辑源，前端只是视图层。zen 网关（OpenAI/Anthropic/Google 兼容端点 + IP/Key 限流 + sticky provider + usage batching）也以 routes 形式内嵌在 app 中，与 UI 同仓库部署。

改造关联

本机未修改该包（v1.18.14 原样）；但它是装配层认知的官方对标物：本机 deepseek-v4-pro/flash 模型配置、opencode.jsonc provider 结构（modalities/variants/cost 字段）即是对 console 的 ZenData ModelSchema/ProviderSchema 的本地简化仿写。

⑥ 怎么用（how）

怎么用

SolidStart (SolidJS) 前端 SPA：bun dev 启动 vite dev 服务器（--host 0.0.0.0）；bun run build 先跑 script/generate-sitemap.ts 生成 sitemap，再 vite build 产出 .output，随后调 ../../opencode/script/schema.ts 把 opencode 的 config.json/tui.json schema 注入 .output/public/。生产形态是 SST/Cloudflare 部署的 SSR 站点（entry-server.tsx 用 createHandler 做 locale/dir 服务端渲染，routes/ 下同时存在 API 路由如 openapi.json.ts、honeycomb/webhook.ts、feishu.ts 重定向）。

典型场景与协作

opencode 官方商业控制台前端（https://opencode.ai）：落地页、登录/授权（auth/）、workspace 管理、账单/订阅/Key/用量仪表盘、Black/Lite 订阅计划页、zen API 网关路由（routes/zen/v1 与 zen/go/v1）、honeycomb 告警 webhook 入口。
