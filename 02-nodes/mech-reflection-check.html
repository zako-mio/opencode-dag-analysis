⑤ 为什么存在（why）

历史引入动机

自进化子系统：每个 Plan+Build 完整周期结束后异步反思，分析本轮执行经验，把可复用知识写入 Memory 或 Skill 轨道，让 Agent 随任务积累越用越强。

当前需求驱动

重构为状态机 + 三池扫描：pending.json(waiting→processing→done)承载 4 层输入，reflection-worker 只读 Reflection 目录+MEMORY 只写 Reflection 目录；处理前对卡 processing 超时条目回退 waiting 防单点阻塞；/reflection 命令做'whether to keep'(确认)与 worker 做'what to learn'(分析)分工。

⑥ 怎么用（how）

触发方式

主 Agent 收到用户消息、在任务分类之前，检查 Reflection/pending.json 的 meta.waiting_count>0；或用户输入 /reflection(或 memory|skill|status|browse)。

工作流/用法

①waiting_count>0→读 pending.json→找最早 waiting cycle→标 processing→写回→委派 reflection-worker 处理反思；②无论成功失败继续正常流程，连续失败 2 次标 expired；③worker 分析 4 层数据→产出 memory/skill 条目→写 pending.json(status=done)；④用户 /reflection→主 Agent 三池扫描→统一分析或逐条 yes/no/edit→确认写入→清理队列(备份→移除→更新 meta→JSON 校验)；⑤处理前超时判定防队列死锁。

协作关系

依赖 command/reflection.md、archive/Reflection/pending.json、skills/agent-reflection/SKILL.md、opencode.jsonc agent.reflection-worker；与 MEMORY 硬门禁(mech-memory-gate)、Mission 留档(mech-mission-archive)协作；output 目标 MEMORY.md 与 Reflection/skills/。
