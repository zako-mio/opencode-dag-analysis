stats-server

oc-stats-server · package · G17-Stats · Layer 1

① 作用

Stats 后端 Node HTTP 服务（Effect HttpRouter + Bun，Dockerfile 部署）。src/server.ts 用 NodeHttpServer 启动 3000 端口服务并注入 Ingest 层，src/router.ts 暴露 GET /health、/ready 与 POST / 数据摄取端点（Bearer 鉴权 + 并发信号量限流），src/ingest.ts 将事件批处理写入 AWS Firehose，src/stat-sync.ts 是每小时 Athena 同步 daemon。

② 提供能力

· 摄取端点 POST /：事件批收 + Firehose 写入（src/router.ts:25、src/ingest.ts:38）
· 健康检查 GET /health 与 /ready（含优雅停机判定，src/router.ts:23-24）
· Bearer 鉴权（timingSafeEqual，src/router.ts:56）
· 每小时统计同步 daemon（src/stat-sync.ts:13）
· Docker 化部署（Dockerfile:1，turbo prune + bun install）

⑤ 为什么存在（why）

设计意图（官方）

独立常驻 Node 服务承担 HTTP 接收 + Firehose 写湖，因为：1) Worker 直连 Firehose 的批处理/重试逻辑需要长驻进程承载；2) 与 console-function 的 honeycomb 直写并行，形成 honeycomb（实时观测）+ lake（数仓）双通道；3) 用 Effect Layer 组合 Ingest/Routes/Server，测试性高。

改造关联

本机未改。装配层无对应物；但本地 agent 采集→HTTP 上报→批量入湖链路与 headroom CLI 的 savings 统计（本地记录压缩收益）是同类 telemetry 思路。

⑥ 怎么用（how）

怎么用

bun src/server.ts 启动（package.json start）：NodeHttpServer（PORT 默认 3000 / HOST 0.0.0.0）承载 Effect HttpRouter；router.ts 挂 GET /health、GET /ready（关停时 503）、POST /（带 Bearer 鉴权 isAuthorized + 8 并发 Semaphore 的 ingest 端点）；ingest.ts 用 @aws-sdk/client-firehose 把事件按 database.table 路由批量写 Kinesis Firehose（500 条/批、3 次重试、退出信号优雅关停）。

典型场景与协作

Zen 网关日志的接收-转发服务：console-function 的 log-processor（Worker）把 lake ingest 事件 POST 到 stats-server，stats-server 校验鉴权后写入 Firehose → 数据湖 → Athena 供 stats-core 查询。
