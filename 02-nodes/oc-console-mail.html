console-mail

oc-console-mail · package · G16-Console · Layer 0

① 作用

邮件模板包：无 src/，全部为 emails/ 下的 jsx-email 模板与共享组件/样式。emails/templates/InviteEmail.tsx 是唯一业务模板（workspace 邀请邮件），被 console-core 的 User 邀请逻辑动态 import 渲染（console/core/src/user.ts:142）。包 exports 映射到 ./emails/templates/*，纯前端渲染无服务逻辑。

② 提供能力

· InviteEmail 邀请邮件模板（React/jsx-email，emails/templates/InviteEmail.tsx:26）
· 共享邮件组件与内联样式（emails/components.tsx、emails/styles.ts）
· 静态邮件资源：字体 woff2/logo/箭头图（emails/templates/static/）
· 本地预览命令（email preview emails/templates）

⑤ 为什么存在（why）

设计意图（官方）

邮件模板独立成包并用 JSX 组件化渲染（@jsx-email），原因：1) 与业务逻辑隔离，纯展示层可单独预览迭代；2) JSX 类型安全 + 复用组件（styles.ts）；3) console-core 的 AWS SES 只负责发送，模板与发送解耦，模板可被 app/core 两处引用。

改造关联

本机未改。装配层的邮件能力另起炉灶（recruit-assist 用 lark-cli/飞书或 minimax-docx），未采用 SES 邮件链路。

⑥ 怎么用（how）

怎么用

纯模板包：exports 映射 ./emails/templates/*（InviteEmail.tsx 等），用 @jsx-email（render/cli/all）把 React/TSX 组件渲染为 HTML 邮件；bun dev = email preview emails/templates 本地预览。被 console-core/console-app 以 workspace:* 依赖，配合 AWS SES（aws.ts 的 SendEmail）发送。

典型场景与协作

控制台的邀请/通知邮件模板（InviteEmail），与 billing/subscription 流程联动（付费邀请、黑金计划等场景）。
