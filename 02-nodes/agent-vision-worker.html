⑤ 为什么存在（why）

历史引入动机

原先 pdf-worker/drawio-worker 曾绑定 vision-exp 模型以看图，0826 解绑改走外部 VLM/read.ts；但通用图片理解仍缺一个专职视觉执行者，故 0822 独立抽象出带 DeepSeek 视觉模型的子Agent。

当前需求驱动

需要图片理解/截图分析/UI对照还原能力，且主Agent已换用 vision-exp 具备看图，委派链路上需要一个明确可路由的视觉执行角色。

⑥ 怎么用（how）

触发方式

被 agent-protocol 的 MCP 路由规则触发：通用图片理解/截图分析/UI还原 → 委派 vision-worker 子Agent（DeepSeek 视觉模型）。

工作流/用法

直接以图片作为输入理解内容、分析截图、做 UI 还原。

协作关系

与 pdf-worker(文本/OCR链路)、drawio-worker(图表导出) 分工；供 agent-protocol 路由；依赖 deepseek 官方 provider 的 deepseek-v4-flash-vision-exp 模型。
